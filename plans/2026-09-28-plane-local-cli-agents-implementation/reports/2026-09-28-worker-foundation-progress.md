## Implemented

- The Worker accepts only a localhost Plane API origin and does not follow HTTP redirects or use an HTTP proxy for its service token.
- The service token must be in a private regular file outside the Run root.
- The configured Run root must be outside the Plane deployment checkout and private to the Worker user.
- A Run clone path is derived from the Run UUID.
- The repository identity requires a matching HTTPS GitHub clone URL and a valid base branch.
- Reusing a clone checks its Git root, origin remote, and clean working tree.
- Clone commands disable terminal prompts and Git file and external protocols.
- A macOS sandbox profile blocks host file writes, Plane checkout reads, and Worker token reads for Q&A processes.
- The Worker polls pending Runs, fences each action with its lease, renews the lease, and streams Claude events to Plane.
- The pending query filters by Harness and turn before its limit, so unsupported Runs do not occupy Claude pickup slots.
- A stopped Harness process settles before Plane records Stop or starts the next Send now turn.
- Follow-up turns reuse the Run clone and receive current issue data, recent same-Run turns and messages, and later issue comments.
- Follow-up context has explicit item and text bounds with omission counts, and it excludes Agent conclusion comments from other Runs.
- A queued message changes to accepted after Harness output confirms delivery, or to interrupted if the Harness fails before confirmation.
- If the Worker lease expires during delivery, Plane marks the unconfirmed message interrupted and rejects the old Worker.
- Claude output and queued Worker events have bounds, and long text blocks retain all content through smaller events.
- Plane can record a failed result before clone registration and fences a lease when repository access disappears before registration.
- The Worker keeps a private process record per Run, checks process identity before a retry, and stops the old process group before requesting a recovery lease.
- An uncertain or still active old process blocks recovery and leaves the Run Stale.
- Recovery reuses Plane's committed same-turn observations and accepted message without dispatching that message again.
- Worker startup reconciles registered process groups before accepting new work.
- The Worker polls pending Harness connection probes and sends a versioned report to Plane through its local token API.
- A probe uses the same macOS read-only boundary for Claude Q&A behavior and records seven explicit checks.
- The Claude command uses safe mode and restricted settings so user hooks do not run inside an Agent turn.
- Codex model discovery uses a metadata-only app-server session with no work-item prompt or tool request.
- The Worker stops and clears the registered metadata process after Codex model discovery.
- The current installed CLI versions are Claude Code 2.1.280, Codex CLI 0.157.1, Grok CLI 1.0.41, and Omp 18.1.21.
- The candidate protocol documentation was checked against the current [Claude CLI reference](https://code.claude.com/docs/en/cli-usage), [Codex app-server protocol](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md), [Grok headless guide](https://docs.x.ai/build/cli/headless-scripting), and [Omp RPC protocol](https://github.com/can1357/oh-my-pi/blob/main/docs/rpc.md).

## Commit snapshot foundation

It preserves added files, deletions, executable bits, and symlink target bytes without following a symlink target.

File reads use 64 KiB chunks; memory does not grow with a single file's content size.
The scan currently reads all tracked file bytes, so its I/O cost remains linear in repository content.
A trusted stat cache would need direct evidence that it preserves exact change detection.
The helper currently rejects repositories with submodule entries rather than silently omitting them.
