Kỹ thuật 05 · Failure Analysis

BA NỖI SỢ

Sai repo · CLI hết hạn · Docker nuốt RAM

người dùng Ba hỏng đáng sợ nhất: nhầm repo, login CLI hết hạn, Docker ăn RAM.

01 · Sai repo

Không bao giờ mặc định cwd Mini (repo Plane). Code escalate phải bind repo trước — map project→git hoặc elicitation — không thì từ chối docker write.

02 · CLI logout

Preflight claude/codex auth trên Mini trước in_progress. Fail Agent Run bằng error activity + comment. Không để container treo.

03 · RAM Docker

Stack Plane chia Mini. Trần số container agent + mem_limit từng hộp + chừa RAM cho Plane. At-capacity = từ chối cứng, không queue rồi vẫn boot docker.

ngành Không đoán câm (Linear user đốt credit vì sai repo). Resolve lớp: map project/team→repo đứng, override comment/label, elicitation nếu 0 hoặc >1. Copilot mặc định repo GitHub của issue — default đó không tồn tại trên Plane/Linear. Codex last-used-env là chân súng đã ghi trong docs.

khóa v1 bind repo: project Plane map một git remote (config đứng). Comment được override. 0 hoặc >1 ứng viên → elicitation trên cùng run, không docker write cho tới khi bind. Không Mini cwd. Không last-used.

hướng Không phải job nào cũng cần Docker. Câu hỏi không cần container. Đã có CLI OS sandbox (Seatbelt / Codex workspace-write) — đừng với Docker chỉ để trả lời câu hỏi về code.

coach Ba tầng: (1) Q&A chỉ issue = không sandbox, không git. (2) Q&A đọc code = CLI OS sandbox trên Mini, không docker, không nhánh/PR. (3) Implement = docker + worktree + named branch. Docker là cô lập cho ghi/đồng thời — không phải để hỏi.
